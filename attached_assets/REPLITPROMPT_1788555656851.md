## What was broken, and why the preview stayed blank

Two independent faults. Either alone was enough.

1. **The server bound to loopback only.** It called `listen(port, callback)` with
   no host, so Node bound `127.0.0.1`. The process was healthy *and* unreachable
   at the same time — which is exactly why Replit reported the app as running
   while the preview never came up. Replit's preview proxy sits outside the
   process and can only reach a listener on `0.0.0.0`.
2. **There was nothing at the root to show.** The transport served JSON only: no
   `GET /`, no static files. Even with the bind fixed, a browser would have got a
   404 JSON body.

## What changed

- The server binds `0.0.0.0` by default, overridable with `HOST`. `.replit` sets
  `HOST = "0.0.0.0"` explicitly so it cannot regress silently.
- A minimal static layer, and a Detent-branded status page at `/` that checks the
  health endpoint live and links to the widget panel and the install snippet.
- The static layer is tried before the router but answers only for `GET`/`HEAD`
  against a real file with a recognised content type, so no API route can be
  shadowed by a file on disk. Path resolution refuses parent-directory segments
  outright rather than relying on normalisation to clamp them.
- `tests/static-serving.test.ts` covers literal, percent-encoded, nested and
  NUL-byte traversal. **387 tests pass** (was 376).

Nothing else moved. The API, the connectors and the governance pipeline are
untouched.

## How to not burn credits

Replit charges per **Agent** request. The Shell is free. The cost driver is how
many times the Agent re-reads your code and retries, and the expensive mistake is
letting it treat a finished repository as one to **build**.

1. **Do the update in the Shell.** See the top of this file. Zero requests.
2. **If you must use the Agent, give it the exact commands.** They are below.
3. **Tell it what not to touch.** Without that it will "helpfully" refactor
   `packages/core` and you pay twice — once to do it, once to undo it.
4. **Never let it change a test to make the suite pass.** A green run bought that
   way costs more than it saves.
5. **Stop at green.**

Budget for this update: **one Agent request, two at the outside.** Past three, go
back to the Shell.

| Task | Shell command | Expected |
|---|---|---|
| Run the tests | `pnpm test` | `387 passed` |
| Typecheck | `pnpm typecheck` | no output |
| Start the API | `pnpm serve` | `listening on 0.0.0.0:8787` |
| Check the page | `curl -s -o /dev/null -w '%{http_code}' localhost:8787/` | `200` |
| Check health | `curl -s localhost:8787/health` | `{"status":"ok",...}` |
| No dependencies at all | `pnpm test:fallback` / `pnpm serve:node` | `387 passed` |

## If everything fails at install

The project runs with no dependencies at all. From a clean checkout:

```
pnpm test:fallback     # 387 tests on Node alone
pnpm serve:node        # the API on Node alone
```

Both use Node 22's own TypeScript transform via two small resolve hooks. If those
work, the product is fine and the problem is the package firewall, not the code.

## Do not

- Do not run `pnpm install --no-optional`. It breaks esbuild's platform binary,
  which tsx needs, and turns a working install into a broken one.
- Do not change a test to make the suite pass.
- Do not set `HOST` to anything but `0.0.0.0` in Replit.
