## What changed, and why

The first attempt failed at install. Replit's package firewall returned a 403 on
`vitest-2.1.9.tgz`, `pnpm install` aborted, the workspace symlinks were never
created, and `pnpm typecheck` then produced 260 cascading errors starting with
`Cannot find module '@detent/awa-core'`.

**That was a packaging fault on our side, not a Replit problem.** A test runner
is not a runtime dependency, and it should never have been able to take an
install down with it. Three changes fix it, and all three are verified against a
simulated firewall:

1. **`vitest` moved to `optionalDependencies`.** A registry refusing it now
   leaves a warning instead of aborting. Verified: install completes, all 20
   workspace links resolve, typecheck is clean.
2. **A built-in test runner.** `tools/mini-test.ts` implements the Vitest subset
   this suite uses, so the tests run unmodified with no vitest present. Both
   runners produce the same result: **376 passed.**
3. **A dependency-free runtime.** Node 22 runs the entire product from source
   with **no `node_modules` at all**, via two small resolve hooks. Verified from
   a bare checkout: 376 tests pass, both demos run, the server starts and
   answers.

`pnpm serve` and `pnpm test` pick the best available option automatically. You
should not have to think about any of this.

## How to not burn credits

Replit charges per Agent request, and the cost driver is how many times the
Agent has to re-read your code and re-try. This repository is built, typechecked
and tested. The expensive mistake is letting the Agent treat it as a project to
**build** rather than one to **run**.

1. **Do not ask the Agent to write features.** They are written.
2. **Give it the exact commands.** They are in the prompt below.
3. **Tell it what not to touch.** Without that it will "helpfully" refactor
   `packages/core` and you pay twice — once to do it, once to undo it.
4. **Use the Shell for anything repeatable.** Re-running tests, restarting the
   server and reading logs are free in the Shell and cost a request each through
   the Agent.
5. **Stop at green.**

Realistic cost: **two to three Agent requests.** Past five, go back to the Shell.

| Task | Shell command |
|---|---|
| Run the tests | `pnpm test` |
| Typecheck | `pnpm typecheck` |
| Run a demo | `pnpm demo` / `pnpm demo:customer` |
| Start the API | `pnpm serve` |
| Run with no dependencies at all | `pnpm test:fallback` / `pnpm serve:node` |

STEP 4 — Run
    pnpm serve
.replit is already configured for port 8787 mapped to 80. The server prints a
widget key, a tenant admin key and a platform key on boot. These are development

Substitute the widget key the server printed:

    curl -s -XPOST localhost:8787/v1/sessions \
      -H "authorization: Bearer <WIDGET_KEY>" \
      -H 'content-type: application/json' \

    curl -s -XPOST localhost:8787/v1/sessions/<SESSION_ID>/messages \
      -H "authorization: Bearer <WIDGET_KEY>" \
      -H 'content-type: application/json' \
      -d '{"text":"do you do contract reviews?"}'

The first returns a session id and an AI disclosure. The second returns a reply.

IF EVERYTHING FAILS AT INSTALL

## After it is running

Shell work. None of it needs the Agent.

```bash
pnpm demo           # three visitor journeys with the audit trail
pnpm demo:customer  # the flagship: declining to sell to an unhappy customer
```

`demo:customer` is the one to show anybody evaluating this. The same customer,
with the same CRM record, in three situations — and the assistant behaves
differently in each, because it reads billing and support and no competitor does.

### The dependency ladder, if you are curious

| Runner | Needs | Used when |
|---|---|---|
| vitest | `vitest` | installed and allowed |
| built-in, under tsx | `tsx` | vitest blocked |
| built-in, on Node | nothing | both blocked |

All three run the same test files unmodified. The built-in runner lives in
`tools/mini-test.ts` and implements only the Vitest surface the suite uses —
deliberately, so anything it does not support is a compile error in a test
rather than a silently passing assertion.

### Serving the widget

No build step. Serve `packages/widget/public/` statically, or copy
`panel.html`, `install.html` and `detent-logo.svg` into a static directory. The
loader is configured from `data-*` attributes on the script tag — see
`packages/widget/public/install.html`.

### Going to a real deployment

Three swaps, none of which change any calling code:

| Swap | Where |
|---|---|
| `ScriptedModelProvider` → a real provider | `PlatformOptions.model` |
| In-memory stores → Postgres | `PlatformOptions.auditStore`, `connectionStore` |
| Sandbox connector → a real CRM | `PlatformOptions.connectors` |

Read `db/README.md` before wiring Postgres. The `SET LOCAL app.tenant_id`
requirement is the most dangerous thing to get wrong: a plain `SET` survives the
transaction back into a pooled connection and becomes another request's tenant
context.

### One honest warning

Replit's Agent is optimised for building things, and this is built. Every request
spent asking it to "improve" or "modernise" moves a working system away from a
known-good state. The tests are the contract; the Agent has not read the three
specifications this implements and cannot know which behaviours are deliberate.

If you want a change, describe it to me and take the diff back to Replit as a
paste.
