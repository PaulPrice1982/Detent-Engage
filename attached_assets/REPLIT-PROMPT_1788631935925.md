## 1. Apply the zip (Shell)

Unzip `detent-agentic-website-assistant.zip` and copy its **contents** over the
workspace root. The workspace root is the contents of
`agentic-website-assistant/`, not a folder containing it.

```bash
cd ~/workspace
unzip -o detent-agentic-website-assistant.zip
cp -a detent-agentic-website-assistant/. .
rm -rf detent-agentic-website-assistant detent-agentic-website-assistant.zip
```

## 2. Remove anything a security scan will stop the deploy for (Shell)

```bash
rm -f CONSOLE-PASSWORD.txt
rm -rf attached_assets/*.zip
```

Both have blocked a publish before. A file named for a password is exactly what
a deployment scan exists to find, and an old release zip is scanned too: one
containing a fixture from before a fix fails a publish the current source
passes.

## 3. Install, build and test (Shell)

The widget is now compiled for the browser as well as for Node, so the build has
two steps. **Do not skip the second**: without it `/widget/loader.js` does not
exist and the assistant does not appear on any page.

```bash
pnpm install
pnpm build          # runs tsc --build AND the widget browser build
pnpm audit
node tools/test.mjs
```

Expected, exactly:

- `pnpm build`: no output. Any output is an error.
- `pnpm audit`, `No known vulnerabilities found`.
- `node tools/test.mjs`: the last line reads `Tests  N passed` with **no
  `failed`**, and no line begins `FAIL`.

  **Judge it on failures, not on the count.** At the time of writing the count
  is 40 files and 811 tests, but that number changes with every release and a
  prompt quoting a stale one stops a perfectly good build. The number that
  matters is zero failures.

  A higher count than the one above is a later release, not a problem. A test
  file count *lower* than 40 means the zip did not fully apply, check the
  extraction rather than the tests.

If `pnpm audit` reports anything, **stop and report it**. A critical advisory
blocks the deploy, and the finding will be in the dependency tree rather than in
anything that changed here.

## 4. Set the secrets

In **Secrets**, not in a file, and not in this prompt:

| Secret | Needed for |
| --- | --- |
| `DATABASE_URL` | **Required in a deployment.** Postgres connection string. Without it the app refuses to start rather than losing every account on the next restart. |
| `DETENT_SESSION_SECRET` | Signs session cookies. Unset, one is generated per boot and every customer is signed out at each restart. |
| `DETENT_CONSOLE_PASSWORD` | Back office sign-in. Without it no operator exists in a deployment. |
| `DETENT_CONSOLE_EMAIL` | The operator's address. |
| `DETENT_BASE_URL` | Absolute links in emails. Unset, password reset links point at localhost. |
| `DETENT_MARKETING_HOST` | `www.detent.co.uk`, **only once DNS points at this app.** Leave unset until then. |
| `DETENT_APP_HOST` | `www.detent.co.uk`: the customer area shares the public domain. Leave unset until DNS is live. |
| `DETENT_CONSOLE_HOST` | `app.detent.co.uk`: the back office, on its own hostname. Leave unset until DNS is live. |
| `DETENT_CONSOLE_ON_PLATFORM_HOST` | `true` **only** while there is no custom domain, so the back office is reachable at `/console` on the Replit URL. Remove it the day `DETENT_CONSOLE_HOST` starts resolving. |
| `DETENT_EMAIL_PROVIDER`, `DETENT_EMAIL_API_KEY`, `DETENT_EMAIL_FROM` | Sending real email. Unset, messages print to the console and say they were not sent. |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Taking payment. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Sign in with Google. |
| `APPLE_CLIENT_ID`, `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` | Sign in with Apple. |

**Set the three host variables only once DNS actually points at this app.** The
Replit hostname is always served, so with them unset everything works at the
deployment URL. Set to a domain that does not yet resolve here, they are simply
hostnames nobody arrives on, and every request lands on the Replit hostname,
which those settings do not describe. The boot banner prints every hostname that
will be answered; compare it against the URL in the browser.

A deployment **refuses to start** if `DETENT_CONSOLE_HOST` shares a hostname with
the marketing, customer or reseller surface. That is deliberate: sharing it means
the back office is reachable from a customer domain.

Add a **PostgreSQL** database from the Replit tools panel. It sets

## 6. Run it (Shell)

```bash
node tools/doctor.mjs      # checks the port is free and the runtime is right
pnpm start
```

Expect `Detent Agentic Website Assistant listening on 0.0.0.0:8787`, and these
three lines, which are the ones worth reading:

```
  migrations       applied 0001_init.sql, 0002_platform.sql
  storage          Postgres, data survives a restart
  restored         1 tenants, 14 knowledge chunks
  hostnames        detent-agentic-assistant.replit.app
```

If a page 404s, check the `hostnames` line first. A request arriving on a
hostname that is not on it gets a 404 on every page, and the server log says
what arrived and what was recognised.

If `storage` says **IN MEMORY**, `DATABASE_URL` is not set and everything will
be lost at the next restart. In a deployment the app will have refused to start
instead.

## 8. Prove data actually survives (Shell)

The single most important check in this release. Sign up a customer in the app,
then stop and start the process, then sign in as them again.

```bash

psql "$DATABASE_URL" -c "select count(*) from auth_user;"
psql "$DATABASE_URL" -c "select count(*) from knowledge_chunk where state='PUBLISHED';"
```

Both must be non-zero after the restart, and the customer must be able to sign
in with the password they set before it.

## What changed in this update

**The assistant did not work in a browser at all, for three separate reasons.**
All three are fixed and all three are verified.

- `loader.js` was never built. It existed as TypeScript and not as anything a
  browser could load, so the snippet on the install page: the one every
  customer is told to paste, returned 404. The widget now compiles to native
  ES modules with no bundler.
- The back office's content security policy was applied to every page. Refusing
  all script is right for the console and stopped the assistant loading
  anywhere else. Each site now carries its own policy.
- The launcher built its panel URL in a way that threw on a relative URL, so the
  panel silently never opened.

**Every API POST hung for ever.** The site mount matches every path, so an API
request had its body read there, was declined, and then waited on a stream that
had already ended. That is every conversation the widget starts.

**The assistant could not answer from knowledge.** Retrieval ran after the model
had already answered and the result was never given back to it. There is now a
second pass, and a provider that answers from approved knowledge and refuses
anything else, including, tested, the capital of Peru.

**New in this release:** an agentic support area inside the customer's account
(27 articles, honest refusal, escalation to a person); the reseller channel with
exclusive postcode territories, 20–50% volume commission bands and a partner
portal on its own login; a *Become a reseller* page; lead routing by type,
source and MQL/SQL; and five recorded demonstrations of the running app.

## Persistence, which is what changed most

Everything was in memory. Accounts, sign-ins, subscriptions, invoices, credit
ledgers, the website, the channel, support requests, tenants, knowledge and the
audit trail now live in Postgres. Set `DATABASE_URL` and it uses them; leave it
unset and it uses memory and says so at boot. A deployment without one refuses
to start rather than taking payment for data it is going to drop.

Three guarantees moved into the database, where they cannot be forgotten: one
open reseller link per customer, one holder per postcode area, and one ledger
entry per idempotency key. Invoice numbers come from a single atomic statement,
because a gapless sequence is a legal requirement and a read-then-write hands
two concurrent issues the same number.

## Check the SEO output (Shell)

New in this release, and the reason to look: the site was structurally
invisible to a search engine before it.

```bash
BASE=http://localhost:8787

# One canonical address per page.
curl -s $BASE/ | grep -o '<link rel="canonical"[^>]*>'

# Generated from the published pages, not typed by hand.
curl -s -o /dev/null -w "robots  %{http_code} %{content_type}\n" $BASE/robots.txt
curl -s -o /dev/null -w "sitemap %{http_code} %{content_type}\n" $BASE/sitemap.xml
curl -s $BASE/sitemap.xml | grep -o '<loc>[^<]*</loc>'

# Structured data. Expect Organization, WebPage, SoftwareApplication, FAQPage.
curl -s $BASE/ | grep -o '"@type":"[A-Za-z]*"' | sort -u
```

Expected: robots.txt is `text/plain`, sitemap.xml is `application/xml`, and the
sitemap lists only published pages.

**The canonical host matters here.** Whichever hostname you visit, the canonical
tag names the one true address, and a page served on any other hostname asks not
to be indexed. That is deliberate: the app answers on the Replit hostname as
well as a custom domain, and without it the two compete for the same words. So
until DNS points at this app, the site correctly tells crawlers not to index the
Replit URL. Nothing to fix, and nothing to do about it except point the domain.

Two claims to verify before the data-protection section is public, because
neither is a fact about the code:

- **"Your data stays in the UK."** Confirm the region of the PostgreSQL database
  this app is using. The claim is about where you deploy, not about the source.
- **Voice.** If OpenAI Realtime is enabled, audio leaves the UK. Either say so or
  do not make the claim.

## What is still not production ready

- **No backups.** Replit's Postgres has its own; confirm the retention before
  you rely on it.
- **PDF and DOCX text extraction** is not implemented, so the knowledge agent
  cannot read the formats customers will upload most.
- **Stripe is not wired into signup**, so the activation fee cannot be taken.
- **Sign in with Apple** needs its ES256 client secret generated; it is a
  short-lived JWT, not a static string.
- **Voice audio transport** is not proven end to end.
- **No rate limiting on public endpoints and no error reporting.**
- A few smaller stores, payments, approvals, consent, metering, outcomes , 
  are still in memory. None holds anything a customer would notice losing, but
  metering feeds billing and should be next.
